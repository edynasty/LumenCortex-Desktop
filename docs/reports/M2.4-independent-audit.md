# M2.4 - Independent acceptance audit (Desktop model integration)

Status: **COMPLETE** (started 2026-10-14, finished 2026-10-15). Verdict: **accepted after fixes** (section 1).

## 1. Verdict

M2.4 meets the Desktop/Core contract. All configuration and model resolution goes through Core, there is no Desktop provider fallback, and no credentials appear in bridge results or errors.

The audit found three defects that tests did not catch and one known P3. All four are fixed in the follow-up commit, each with a regression test that fails without its fix (section 5). The remaining spec deviations are minor UI differences, recorded in section 3 and not fixed here.

## 4. Evidence and reproductions

- **F1**
  - The owner's probe `TestAuditProbeRenameDropsUnmanaged` logged the file after a rename with `headers`, `timeoutSeconds`, `toolCalling` and `reasoning` gone.
  - Real app (`wails dev`, isolated `XDG_CONFIG_HOME`): renaming provider `smoke` → `smoke2` and model `fake-chat` → `chat-renamed` through the panel now keeps `headers {X-Org}`, `timeoutSeconds 45` and `reasoning {deepseek}`.
  - The next run sent `X-Org: smoke-org` upstream.
- **F2**
  - `json.Marshal(ProviderCatalogScope("global"))` on a fresh config: `"catalog":{"$schema":"…"}`, with no `providers`.
  - A component test fed that document reproduced the unhandled `TypeError … reading 'deepseek'`.
  - Real app after the fix: the first provider saved and discovery added `fake-chat`.
- **F3**
  - Restoring `overflow: hidden` makes the four "thread model picker receives clicks" specs fail at 1440/1180/820/560 px; without it, all 8 picker specs pass.
  - Real app: the search input and the option are the topmost elements under their centers.
- **F4**
  - Real app: after the pinned model `smoke2/chat-renamed` was renamed outside the app, the thread picker shows `smoke2/chat-renamed（不可用）`, while the new-task picker shows the new default.
- **F5**
  - Real app: changing `lumencortex.json` outside the app followed by a window `focus` event updated the picker without a reload.
  - The owner's stale-response test failed for a test-harness reason, not because of the guard (section 5).

| F5: focus reload and newest-read-wins guard | `useWorkspaceController.ts` | `useWorkspaceController.test.ts`: "reloads … when the window regains focus" (fails without the listener) and "never lets an older configuration response replace a newer one" (fails without the guard) |

**Why the stale-response test failed.**
- The test queued one-shot `configState` mocks, but mount reads twice (before and after `state.workspace` is known). The queue ran dry, a read returned `undefined`, and `config` became `undefined`.
- The test also passed a new `setError` function on every render. That re-created `refreshConfig`, which reran the effect on every render, so a fresh read always overwrote the stale one. The test therefore passed even with the guard removed.
- Fix: a mock that returns the current config, and a stable `setError`, as React's setter is in the app.

**Contract test widened:** `TestWireTypesMatchGoDTOs` now also covers `ProviderCatalog`, `ProviderDefinition` and `ProviderModel`; before, the provider-panel DTO types were unchecked.

**Probe tests promoted:** the owner's untracked `zz_audit_probe_test.go` became asserting tests in `config_test.go` and the probe file was deleted:
- `TestConfigErrorsDoNotEchoSecrets` (literal key, invalid header, truncated file);
- `TestConcurrentSavesFromOneReadHaveExactlyOneWinner` (8 writers);
- `TestTrustThroughSymlinkStoresCanonicalPath`.

The explicit-empty probe was already covered by `TestSaveProviderCatalogScopePreservesUnmanagedFields` ("explicit empty").

## 6. Desktop/Core contract verification

A read-only comparison of the spec's Desktop API section against the code (scout, cross-checked):
- the bound methods, DTOs and TS wire types match the spec, except D6;
- `ConfigState`, `ModelInfo`, `ConfigWarning` and `ProviderCatalogDocument` are Core types or exact projections;
- Start and Continue go through `Supervisor.Start` with `ModelRef`; Desktop has no `ProviderFactory`;
- all 10 strings in `frontend/src/lib/core-errors.json` equal the pinned Core sentinels (`TestFrontendCoreErrorMarkersMatchCoreSentinels`).

Core config sentinels without a dedicated UI key (`ErrUntrustedOverride`, `ErrCredentialRedirect`, `ErrUnknownProvider`) are shown through warnings or the generic invalid-config message.

## 7. Configuration and security results

- **No Desktop fallback:** Desktop has no provider resolution, no `LCX_*` model/key fallback and no implicit endpoint in production code. The only `LCX_*` names are in `testutil_test.go`, which unsets them.
- **Secrets in errors:** a literal key, header values in a schema-invalid file and a truncated file never appear in bridge errors (`TestConfigErrorsDoNotEchoSecrets`).
- **Secrets in results:** `TestBridgeResultsCarryNoCredentialsAcrossARun` passes.
- **Concurrent saves:** exactly one wins; the rest get `ErrConflict` and the file holds only the winner's change (also under `-race`).
- **Trust:** an entry made through a symlink stores only the canonical path.
- **Key handling (real app):** the key was stored as `{env:LCX_SMOKE_KEY}` and sent upstream as `Authorization` (`auth: set` in the fake provider log). The value never appeared in the file.

## 8. Real Wails application acceptance

The app ran under `wails dev` (real Go bindings, Chromium against the dev server) with an isolated `XDG_CONFIG_HOME`, a temporary Git repo and a local fake OpenAI-compatible provider. Steps:

1. Fresh config: the panel showed an empty catalog. I added provider `smoke` with `LCX_SMOKE_KEY`, discovered `fake-chat` and set it as default.
2. I added `headers`, `timeoutSeconds` and `reasoning` to the file by hand, then renamed provider and model in the panel: all of them were kept (F1).
   - Two side observations: an invalid hand edit (`modalities.output`) was refused by Core and shown as "nothing written"; an out-of-band edit while the panel held the old digest was shown as a conflict and reloaded.
3. I opened the repo and started a task with no explicit model: the session was pinned to `smoke2/chat-renamed`, and the request carried upstream model `fake-chat`, `Authorization` and `X-Org`. Result "smoke ok".
4. I renamed the model to `chat-v2` outside the app and sent a focus event:
   - the thread picker showed `smoke2/chat-renamed（不可用）`, and new tasks showed the new default;
   - the picker popover was fully clickable;
   - choosing `fake-chat` replaced the placeholder.

All smoke artifacts were removed.

**Earlier-Core database (the M2.4 report's open acceptance item).** I copied the owner's untracked `.lumencortex/lumencortex.db` (legacy schema: `metadata.schema_version=1`, no `model_ref`, one session) into temporary workspaces. Both checks went through `backend.Runtime.OpenWorkspace`; the original file was not opened.

- **First open:** the database migrated to `user_version 2` and a backup `backups/lumencortex.db.v0.<ts>` was written. The legacy session loaded with `modelRef ""`. A second runtime then opened the migrated database without error, which is correct: the lock only blocks schema changes.
- **Database in use:** another process held a shared `flock` on `db.lock`. Open returned `ErrDatabaseInUse` after Core's bounded 30 s wait, and the database stayed unmigrated. The message is the exact `core-errors.json` `databaseInUse` marker, which the Desktop routes to workspace recovery (`error-recovery.ts:42`). The 30 s wait cannot be cancelled from the UI (M2.4 report P3).
