# M3.3 - Desktop Task State controls and `recentMessages` removal

Status: **implemented and validated locally; committed to local Desktop `main`, not pushed.** Paired with Core M3.2. Core is pinned to the local commit `977363a`, which is not on `origin` (Core `main` is ahead of `origin/main` by 9). A clean clone of Desktop cannot resolve the pin until Core is published.

## 1. Scope and baseline

- Design row M3.3 (`../LumenCortex-architecture-audit/design/README.md`, milestone table): drop the `recentMessages` run option; "reset context" action; brief and references editor; resolution control. Acceptance: a reset during a run returns `ErrRunHeld`; an edit made during a run is visible in the next step.
- Desktop baseline: `70c187d` (revert of the W3 bridge `b5e9551`, which did not build; recovery report finding F7, `../LumenCortex/docs/reports/oct16-recovery-2026-10-17.md`).
- Core: `9d0fcab` (M3.2 §4.6) plus `977363a`, which exports `runtime.TaskReferenceEdit` and `runtime.TaskResolveEdit`. `TaskStateEdit` aliases `internal/taskstate.Edit`, whose `Reference` and `Resolve` fields have types from an internal package, so a host could set only the brief. The alias change adds no behavior.
- Pin: `github.com/edynasty/LumenCortex v0.0.0-20261017090217-977363abe668` (was `…156fdff946e4`). Resolved with a local `url.insteadOf`. No `replace`, no `go.work`.
- Kept by design: the `Runtime.RecentMessages(limit)` read API (design §4.9 removal table keeps it). Only the run option was removed.
- Not done (out of scope): M4.1, M4.2, Demo changes.

## 3. Tests

- Design acceptance, real Core engine and fake HTTP provider (`internal/backend/taskstate_test.go`):
  - `TestResetContextDuringRunReturnsRunHeld`: reset while a run holds the session returns `ErrRunHeld` and leaves `windowStartSeq` unchanged; after the run, reset moves it to the next transcript seq.
  - `TestBriefEditDuringRunReachesNextStep`: the host view shows the brief as a pending edit during the run; the request sent before the edit lacks it, the next step's request carries it; after the run it is applied.
  - `TestTaskReferencesAndResolution`: include (with note), exclude keeps the note, remove; the host cannot write a `suggested` reference; resolution set by the user with the actor; an unknown resolution is refused; only the 4 accepted edits are pending.
- `TaskStatePanel.test.tsx` (mocked bridge, real copy): resolution set as the user, with obligations hidden once resolved (fails without the guard, passes with it); brief save only when changed, trimmed, with a pending count; exclude a suggestion and add a path; reset disabled while running, `ErrRunHeld` shown as "running elsewhere"; re-read only on this session's Task State events.
- `visual-tests/states.spec.ts`: Task tab at 1440 and 560 px keeps each reference card inside the list. At first, long paths widened the grid item past the panel; the fix is `minmax(0, 1fr)` with `min-width: 0`.
- `model-selection.test.ts`: the agent config no longer carries `recentMessages`.
