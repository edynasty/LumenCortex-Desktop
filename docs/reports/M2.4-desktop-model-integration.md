## 3. Go/Wails API and TypeScript changes

| Wails method | Go | TypeScript |
|---|---|---|
| `GetConfigState() ConfigState` | `Runtime.ConfigState` | `bridge.configState` |
| `TrustWorkspace(globalDigest) ConfigState` | `Runtime.TrustWorkspace` | `bridge.trustWorkspace` |
| `GetProviderCatalogScope(scope) ProviderCatalogDocument` | `Runtime.ProviderCatalogScope` | `bridge.providerCatalogScope` |
| `SaveProviderCatalogScope(scope, doc) ProviderCatalogDocument` | `Runtime.SaveProviderCatalogScope` | `bridge.saveProviderCatalogScope` |
| `StartAgent` / `ContinueAgent` take `AgentConfig{modelRef, effort, ...}` | maps to `AgentOptions` | `AgentConfig` (no `provider` field any more) |
| removed: `GetProviderCatalog`, `SaveProviderCatalog`, `GetProviderSecretStatuses` | - | - |

- `ConfigState` = `{workspace, trusted, model, subagentModel?, failover, models[], warnings[], globalPath, globalDigest}`. `models[]` is Core's `config.ModelInfo` (ref, names, upstream `modelID`, limits, `toolCalling`, modalities, reasoning format, efforts, `apiKeyEnv`, `apiKeySet`) and `warnings[]` is Core's `config.Warning`. Neither carries a key or a header value.
- `ProviderCatalogDocument` = `{scope, path, digest, catalog}`; the digest is Core's `Document.Digest`.
- `Session.modelRef` is `SessionInfo.ModelRef`.
- `GetProviderSecretStatuses` was removed: `ModelInfo.apiKeyEnv/apiKeySet` carries the same fact from Core, so a second source of truth was dropped.
- Bridge contract: `app_test.go` asserts that `AppAPI` in `frontend/src/lib/bridge.ts` and the bound `App` methods are exactly the same set, and that the TypeScript wire types match the Go DTO JSON fields (including `omitempty`).

## 4. Model selection and session pinning

Logic is in `frontend/src/app/model-selection.ts` and `hooks/useModelSelection.ts`; Core keeps candidate choice and failover.

- Picker options = `ConfigState.models` minus `toolCalling: false`. Missing key = `apiKeyEnv` set and `apiKeySet` false (name only, never a value).
- New task: shows `Effective.Model`. Existing session: shows `SessionInfo.ModelRef` (falls back to `Effective.Model` only for a session that is not pinned yet). A later change of the default never moves a pinned session.
- `AgentOptions.ModelRef` is sent only for an explicit choice made on this route that differs from the shown baseline (`chooseModel`, `explicitModelRef`). Choosing the baseline again clears the choice; a choice does not follow the user to another session, a new task or another project.
- A session pinned to a model the picker does not offer (for example `toolCalling: false`) shows the picker placeholder; Continue then returns Core's `ErrModelWithoutToolCalling`, shown as actionable text.
- `effort` is part of `AgentConfig` on the Go side; the UI does not expose an effort control (not requested).

## 5. Configuration and trust

- Reads: `config.Load`, `Effective`, `Catalog`, `Provider`, `ReadDocument`. Writes: `config.Save(path, file, expectedDigest)` only. `docs/lumencortex.schema.json` is Core's `docs.ConfigSchema` byte for byte (`TestSchemaIdentityWithCore`).
- Saves overlay the editable DTO (default `model`, provider name/package/baseURL/endpoint/apiKey, model name/modelID/limit) on the file as read; everything else (`failover`, `subagentModel`, `effort`, `checks`, `trustedWorkspaces`, headers, timeouts, `reasoning`, `toolCalling`, modalities, unknown keys Core preserves) survives. Providers and models omitted by the DTO are deleted; explicit empty collections are preserved. A save that would orphan a model reference in either file is refused with `ErrInvalidConfig` before writing.
- Optimistic concurrency: the UI sends the digest it read; a changed file is `ErrConflict`, nothing is written. The provider panel then reloads the file and the effective configuration; the trust flow refreshes `ConfigState`.
- `TrustWorkspace(globalDigest)` appends the canonical (`Effective.Workspace`) path to the global `trustedWorkspaces` via `config.Save`; it is idempotent for an already trusted workspace and creates the global file when it is missing.
- Provider discovery and connection test use `cfg.Provider(id)` (Core-resolved base URL, endpoint, key, headers), reject redirects off the provider origin and never forward credentials elsewhere.

## 6. UI changes

- Model picker fed by Core's catalog; no raw endpoint or key in everyday UI.
- `components/config/ConfigWarnings` (existing warning-notice look, design tokens only) in the new-task and thread surfaces and at the top of the provider panel: `untrusted_override` (one grouped notice with a "Trust this project" action when Core names the trust entry), `legacy_global_path`, `cognition_profile`, `default_limit` (provider panel only). Unknown codes show Core's original `message`.
- Core errors are matched by sentinel text (`frontend/src/lib/core-errors.json`, kept equal to the pinned Core's sentinels by `TestFrontendCoreErrorMarkersMatchCoreSentinels`) and shown as localized actionable copy in the existing error toast: `ErrDatabaseInUse` (action: reopen project), `ErrSchemaTooNew`, `ErrLegacyNodeDatabase`, `ErrUnknownModel`, `ErrModelWithoutToolCalling`, `ErrInvalidEffort`, `ErrConflict`, `ErrInvalidConfig` (keeps Core's detail), `ErrRunHeld`.
- Opening a project (first-open migration, up to Core's lock wait) marks the workspace as busy until Core answers.
- All new copy is in `lib/i18n/app-copy.ts` (zh-CN and en, key parity tested). TypeScript `lib` raised to ES2024 so tests can use `Promise.withResolvers`.

## 7. Security verification

- `TestBridgeResultsCarryNoCredentialsAcrossARun` runs a real session against an `httptest` provider that requires the key and a credential-bearing header, then asserts neither sentinel appears in the JSON of `ConfigState`, provider documents, discovery results, `Session`, messages or `WorkspaceState`.
- `TestConfigStateReportsCoreCatalogWithoutCredentials`, `TestSaveRejectsLiteralKeyWithoutEchoingIt`, `TestDiscoveryUsesResolvedProviderHeadersAndKey` cover the same boundary for state, save errors and discovery.
- An untrusted workspace provider is not in the catalog, receives no request and Start returns `ErrUnknownModel` until `TrustWorkspace` is called (`TestTrustWorkspaceWritesCanonicalEntryAndEnablesWorkspaceProvider`).
- No hidden reasoning is stored or read by this change; no persistence, compaction or recovery code was touched.
- The frontend stores no key, and the model selection is kept in memory only (no new `localStorage` use).

## 10. Remaining issues and limits

- **P3** First-open lock wait cannot be cancelled from the UI; the UI shows busy until Core returns (Core's lock wait is bounded). Not measured against a large real database.
- **P3** A session pinned to a model not offered by the picker shows the placeholder instead of the ref.
- **P3** `effort` is accepted by the bridge but has no UI control (Core accepts and ignores escalation until M3.1).
- Platform: only macOS (darwin/arm64 host, universal build) was built; Windows and Linux were not built. The Wails app was built but not launched interactively; UI behavior was checked through Vitest and the Playwright visual fixtures.
- `go vet` and `gofmt -l` still flag pre-existing formatting in `app.go`, `main.go`, `internal/backend/context.go`, `lsp.go`, `worktree.go`; untouched by this task.
